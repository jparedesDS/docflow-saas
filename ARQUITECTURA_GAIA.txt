CÓMO GAIA DIFIERE DE TR/ACONEX/SENDOC
──────────────────────────────────────

TR (egesdoc@grupotr.es)
├─ Estructura: multipart/mixed
├─ Contenido: text/html directo ✓
├─ Tabla: En cuerpo HTML
└─ Status: Vía headers en tabla

ACONEX (noreply@aconex.com)
├─ Estructura: multipart/mixed
├─ Contenido: text/html directo ✓
├─ Tabla: En cuerpo HTML
└─ Status: Vía "S.R. Status" column

SENDOC (adminsendoc@corporate.sener)
├─ Estructura: multipart/mixed
├─ Contenido: text/html directo ✓
├─ Tabla: Key-value pairs transformadas
└─ Status: Vía "Step" column

GAIA (gaia/technip)
├─ Estructura: multipart/mixed
├─ Contenido: application/ms-tnef ⚠️ ESPECIAL
├─ TNEF contiene:
│  ├─ htmlbody (ideal) ✓
│  ├─ rtfbody (requiere striprtf)
│  └─ body (texto plano)
├─ Tabla: En htmlbody dentro de TNEF
└─ Status: Vía "Code X" en subject

DIFERENCIA CLAVE:
─────────────────
TR, ACONEX, SENDOC:
  email.walk() → text/html → payload.decode() → HTML string ✓

GAIA:
  email.walk() → application/ms-tnef → TNEF() → tnef.htmlbody ⚠️


PROBLEMA EN CONTEXTO
────────────────────

Línea 99 de imap_service.py:
  tnef = TNEF(tnef_data)  ← Sin try/except

Escenarios problemáticos:
1. tnef_data vacío/corrupto → TNEF() lanza excepción
2. tnef.htmlbody es None → Continúa al siguiente intento
3. tnef.htmlbody vacío pero rtfbody existe → Ignora rtfbody
4. Solo tnef.body existe → Ignora body

Resultado: get_html_body() retorna "" → preview_email() lanza ValueError


SOLUCIÓN EN CONTEXTO
────────────────────

Mejorar get_html_body() para:

1. Try/except alrededor de TNEF
   └─ Captura excepciones sin romper app

2. Fallback: htmlbody → rtfbody → body
   ├─ htmlbody: Ideal, retorna directamente
   ├─ rtfbody: Convierte con striprtf.rtf_to_text()
   └─ body: Escapa HTML y retorna <pre>

3. Logging detallado
   ├─ Qué se encontró (TNEF/HTML)
   ├─ Qué se usó (htmlbody/rtfbody/body)
   └─ Qué falló (si aplicable)
